- Portal root → one `div#productreels-portal.pr-portal`, created on first use **inside** `#productreels-admin-app` (not `<body>`): 1.0.0 content shown inside dialogs is styled under that id and would lose every rule outside it. Everything in it is `position: fixed`. It also tracks the app's inline bounds as `--pr-app-start`/`--pr-app-end`, so toasts and FloatingBar centre on the app, not on a viewport that includes the WP menu. Part 14 may move it to `<body>` once no `wr-*` content renders in dialogs (Claude, part 02).
- Component APIs → text inputs pass native props through (`onChange` gets the event, as in the reference); Checkbox, Switch, Toggle, Segmented, Tabs, FilterChips, RangeField and ColorField call `onChange( value )`. `ColorField` takes `opacity` (boolean) to show and store alpha (#rrggbbaa), otherwise it writes #rrggbb. `RangeField` shows a stored value outside min–max unclamped (AUDIT §7) and clamps only what is typed. `Menu` items: `{ icon, label, hint, danger, disabled, onSelect }` or `'-'`. The toast API is 1.0.0's plus a last `options` argument, `{ icon, action: { label, onClick } }` (5 s, paused on hover or focus). `FloatingBar` portals a fixed bar and leaves an in-flow spacer of its height; toasts move above it while it shows. `Dialog`: `title, description, size, footer, note, noteTone, onClose, initialFocus, body, dismissible`; `ConfirmDialog` accepts `confirm` or 1.0.0's `confirmLabel`, plus `tone` and `busy` (Claude, part 02).
- Stacked dialogs → a module-level stack: only the top dialog handles Escape and traps Tab, and Escape is left to an open popup inside it (any `[aria-haspopup][aria-expanded=true]`), so a Select, colour picker or Menu closes first. A scrim click cancels only when the press started on the scrim (Claude, part 02).
